THE ONE WRONG PREDICTION IS THE INTERESTING RESULT.
NDD's live set does NOT scale linearly with rules. Two points, same topology
and same 520 checks, this machine:

    1,351,800 rules -> 3,519 MB      (k=10)
    4,476,240 rules -> 6,782 MB      (k=3)
    rules x3.31, live set x1.93  =>  live ~ rules^0.548

Linear scaling predicted 11,653 MB and the measurement is 6,782 MB -- a 72%
overestimate. That is plausible for a decision-diagram engine: more rules over
the same 23-device, same-prefix-space topology share more structure. It is a
fit through TWO points, so it is an anchor, not an established law.

CONSEQUENCE 1 -- the heap I chose was unnecessary, and for a reason that was
wrong. K10_RESULT_AND_K3_REVISION.txt raised 12g to 16g because linear scaling
put the live set at ~11.6 GB, "essentially 12g". The live set is 6,782 MB, so
12g (56% occupancy) would have worked. The revision was defensible on the
information then available and cost nothing here, but its stated reason did not
hold. 8g is a different matter: 6,782 MB live in an 8g heap is 85% occupancy,
and the 19 GB machine's 8g runs were killed by the external floor at 4.0-4.5 GB
live, i.e. before reaching this peak -- so they never tested it.

CONSEQUENCE 2 -- the k=1 sizing in 2.15 can be revised DOWN, and it is an
extrapolation from two points, not a measurement.
