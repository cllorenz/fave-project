STOPPING RULES -- declared, identical for every cell, unchanged from the ship
  limit_class  v5 (REPORTABLE)
  limit_wall   86400 s (24 h)
  limit_rss    32768 MB (32 GB)
  memory_floor 2000 MB -- set LOW on purpose: the floor is there to RECORD the
               peak, not to protect the run (§8.2). This machine has NO SWAP,
               so an overshoot is the OOM killer rather than a slowdown.
  status_every 60 s progress trail on every cell.
  Enforcement is external and identical for every engine (harness wall-clock +
  peak-RSS monitor), never RLIMIT_AS, which misfires on the JVM.
  VeriFlow-FR's engine-internal --vf-budget is 0 (off) in every cell.

  A cell killed by a DECLARED limit is a result (status deadline|memory,
  limit_tripped wall|rss). A cell killed by the ENVIRONMENT is status
  interrupted, limit_tripped none -- NOT reportable, and re-run by the queue.

THE ONE ORDERING DECISION THIS SESSION TOOK, AND WHY
  wl_up_vfplain and wl_tum_vfplain are DEFERRED to the end of the whole
  campaign (bench/campaigns/v5_phase_a_dnf.json). Their declared limits are
  UNCHANGED -- v5, 24 h, 32 GB. Only their position in the order moved.

  Why: §5.1 declares both to be did-not-finishes ("2.6e11 ECs predicted at
  pgf.forward_filter"; "1.74e10"), so each is expected to run to its 24 h wall.
  That is 48 h for two cells, inside a phase §6 budgets at 6-10 h -- the
  shipped queue, §5.1's prose and §6's table disagree, and taken literally the
  queue would have spent 48 of the 64 budgeted hours before phase B began.

  Why this is faithful rather than a cut: §6 already says "order long cells
  last and singly, so a crash costs one cell", and VERIFLOW_PLAN.md §4.6 says
  the EC count is stamped at each table BEFORE enumerating. So the scientific
  content of these two cells -- the predicted EC bound that says WHY it does
  not finish -- lands in the first minutes; the remaining 24 h buys only the
  right to write "within 24 h" rather than "within N h". Everything else in
  the campaign is worth more per hour, so it runs first and these run last
  with whatever budget remains.

  If the budget does not reach them, they are recorded as NOT RUN with this
  reason, and no did-not-finish is claimed for them from this campaign. A cell
  that was merely never started has not been shown not to finish.
