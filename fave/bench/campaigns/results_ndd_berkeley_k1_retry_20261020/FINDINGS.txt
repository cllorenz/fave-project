READING
  1. Ingress classes removed the trial's cause: the translation's jump from
     26 to 61 GB is gone, and NDD received rules.
  2. Route streaming did not lower the load's plateau (~26 GB in both runs),
     so the plateau is the FaVe model and the adapter's buffers, not the
     parsed routes.json. The load took ~550 s longer streamed.
  3. The binding memory was the JVM's committed heap, not its live data: with
     a 56 GB cap G1 grew the heap rather than collecting. Live data at the
     stop (9.2 GB) plus the Python side (~26 GB) was ~35 GB.
  4. How far the build was is an estimate: the classes send ~1.96 rules to
     the engine per FaVe rule at k = 300 (112,517 for 57,513), i.e. ~26 M at
     k = 1, so 7.4 M is ~28 %. If the live heap grew in proportion, the build
     would need ~33 GB live, i.e. ~59 GB with the Python side, at the
     machine's edge either way.
